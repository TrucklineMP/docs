VTC 公告可让您的工作人员在 VTC 中发生重要事件时，自动向 Discord 发送更新。例如，成员加入、申请提交或活动取消等。

消息通过您在自己服务器中创建的 **Discord 网络钩子** 发送。您可以选择要公告哪些事件，以及每条消息的呈现方式。

## 要求

- 您的 VTC 必须在 TrucklineMP 上启用 **VTC 公告** 模块。
- 您需要一个可以创建网络钩子的 Discord 服务器（服务器设置 → 集成 → 网络钩子）。
- 配置公告的工作人员需要相应的 VTC 权限（请参阅下方的 [权限](#权限)）。

## 访问公告

1. 打开您的 VTC 个人资料，前往 **管理**。
2. 在管理侧边栏（“成员”下）选择 **公告**。
3. 添加一个网络钩子，然后启用您关心的事件。

每个 VTC 最多可以添加 **10 个网络钩子**。当您需要为不同主题设置不同频道时，可以使用多个网络钩子（例如，一个用于招募，一个用于活动）。

---

## 设置网络钩子

### 创建 Discord 网络钩子

1. 在 Discord 中，打开目标频道。
2. 前往 **编辑频道 → 集成 → 网络钩子 → 新建网络钩子**。
3. 复制网络钩子 URL，其格式为 `https://discord.com/api/webhooks/...`。

### 在 TrucklineMP 上添加

1. 在公告页面，点击 **添加网络钩子**。
2. 为其指定一个清晰的名称（例如 `Staff log` 或 `Recruitment alerts`）。
3. 粘贴 Discord 网络钩子 URL 并保存。

网络钩子 URL 会被安全存储。创建后，列表中仅显示该 URL 的屏蔽版本。

## 权限

通过 [VTC 角色与权限](/zh-cn/web-docs/vtc/roles-permissions/) 分配这些权限：

| 权限 | 用途 |
| --- | --- |
| `announcements.manage` | 创建、编辑和删除网络钩子；更改事件模板；导出配置 |
| `announcements.view` | 查看网络钩子和投递日志 |
| `announcements.test` | 发送测试消息，无需完整的管理权限 |

将 **manage** 权限授予领导层或人力资源角色。将 **view** 权限授予只需确认消息是否成功投递的工作人员。**test** 权限适用于试用人员，他们可以在不更改生产配置的情况下验证设置。

## 配置事件

每个网络钩子都有独立的事件列表。展开某个分组（成员、招募、活动等），然后切换单个事件的启用或禁用状态。

### 默认模板

大多数事件都附带一个合理的默认 Discord 嵌入消息。除非您希望完全控制，否则请保持 **使用默认消息模板** 启用状态。

### 自定义模板

禁用默认模板后即可进行编辑：

- **消息内容**（可选，嵌入消息上方的纯文本）
- **嵌入标题、描述、URL、颜色、页脚**
- **仅针对该事件的网络钩子用户名和头像** 覆盖

使用 **变量**（在配置选项卡的侧边栏中列出）插入实时数据。例如：`**{member.name}** 已加入 {vtc.name}`。

### 批量操作

- 每个分组标题旁的 **全部启用 / 全部禁用** 可切换该分组中所有事件的启用状态。
- **精简**、**详细员工日志** 和 **面向公众的友好模式** 预设可提供初始配置。详细模式会启用所有事件；面向公众的友好模式则启用一组规模较小、面向成员的事件。

### 角色 @ 提醒（可选）

您可以为每个事件设置一个 **@ 提醒角色 ID**（Discord 角色雪flake）。当事件触发时，消息中将包含 `<@&roleId>`，从而通知该角色。

### 条件投递（可选）

您可以为每个事件添加条件：

- **静默时段**：设置时区、开始时间和结束时间（在此期间内将跳过公告）。
- **仅招募开放时生效**：仅在 VTC 的招募处于开放状态时触发。
- **需要特定角色**：仅在受影响成员拥有特定 VTC 角色时触发。

## 模板变量

消息发送时，变量会被替换。常用变量如下：

| 变量 | 含义 |
| --- | --- |
| `{vtc.name}` | VTC 显示名称 |
| `{vtc.handle}` | VTC 标识符（含 @） |
| `{vtc.url}` | VTC 公开个人资料 URL |
| `{member.name}` | 受影响成员名称 |
| `{actor.name}` | 执行操作的工作人员名称 |
| `{role.name}` | 角色名称 |
| `{application.id}` | 招募申请 ID |
| `{news.title}` | 新闻帖标题 |
| `{event.name}` | 活动名称 |
| `{event.url}` | 活动页面 URL |
| `{reason}` | 原因或备注文本 |
| `{timestamp}` | 事件发生的 UTC 时间 |

用户界面会列出所有支持的变量。点击任一变量即可将其复制到模板中。

## 支持的事件

事件在管理界面中按分组显示。除新网络钩子默认启用的“成员加入”、“成员离开”和“成员被踢出”外，所有事件默认均为 **禁用** 状态。

### 成员

- 成员加入
- 成员离开
- 成员被踢出
- 成员被分配角色
- 成员被移除角色

### 招募

- 申请已提交
- 申请已接受
- 申请已拒绝
- 申请已撤回

### 邀请

- 邀请已创建
- 邀请已兑换
- 邀请已撤销

### 新闻

- 新闻已发布
- 新闻已更新
- 新闻已删除

### 活动

- 活动已创建
- 活动已更新
- 活动已取消
- 活动广播（工作人员向参与者发送消息）
- RSVP 已更改
- 活动签到
- 参与者已批准（当需要批准时）
- 活动因开始前无注册而自动取消
- 已请求泊位
- 泊位已决定（已批准或拒绝）

### 角色

- 角色已创建
- 角色已更新
- 角色已删除

### 管理

- 所有权已转移
- 黑名单条目已添加
- 黑名单条目已移除
- 设置已更新
- 招募状态已切换为开放或关闭
- VTC 已解散
- Discord 服务器已从 VTC 解除关联

### 验证

- 验证申请已提交
- 验证已批准
- 验证已拒绝

## 投递模式

### 即时（默认）

每个已启用的事件发生时都会立即发送到 Discord。投递失败时会自动重试（最多三次，并采用退避策略）。

### 每日摘要

当网络钩子启用 **每日摘要** 时，事件会被排队并合并为一条每日汇总帖子，而非即时发送。这适用于高活跃度 VTC，既想保留员工频道，又不希望被持续 ping 提醒。

---

## 应用内镜像（可选）

您可以在网络钩子上启用 **应用内镜像**。当公告消息触发时，拥有 `announcements.view` 权限的工作人员还会在 TrucklineMP 上收到一条应用内通知。这并非替代 Discord，而是为工作人员提供网站内的备用信息源。

---

## 测试、导出和复制

- **发送测试** 会选择一个示例事件，并向 Discord 发送预览消息。测试之间存在较短的冷却时间。
- **复制** 会将一个网络钩子的事件配置复制到新的网络钩子（默认禁用，需您手动启用）。
- **导出** 可将您的模板配置以 JSON 格式下载，用于备份或复制到另一个 VTC。

更改模板或网络钩子 URL 后，请务必运行测试。

---

## 投递日志

打开 **投递日志** 选项卡，可查看所选网络钩子的近期投递记录。

- 可按成功或失败状态，或按事件标识符进行筛选。
- 失败的条目会显示来自 Discord 的 HTTP 状态码和错误文本。
- 对失败条目点击 **重新投递**，可再次尝试投递。

如果网络钩子反复失败，它可能会被 **自动禁用**，以保护您的频道免受损坏的 URL 影响。修复 Discord URL 后，可从网络钩子设置中重新启用。发生此情况时会显示警告横幅。

---

## 网络钩子级选项

除了每个事件的设置外，每个网络钩子还支持：

- **默认用户名** 和 **默认头像**（当事件模板未覆盖时使用）
- 整个网络钩子的 **启用 / 禁用** 切换
- **投递模式**（即时或每日摘要）

## 提示与最佳实践

**为不同受众使用不同频道。** 公开的 `#announcements` 频道可能只需要“成员加入”和“新闻发布”事件。私有的 `#staff-log` 频道则可以使用“详细”预设。

**从小处着手。** 先启用少数几个事件进行测试，然后再逐步扩展。一次性启用所有事件会使难以发现配置错误的模板。

**保护网络钩子 URL 的机密性。** 任何拥有该 URL 的人都可以向您的频道发帖。如果 URL 泄露，请在 Discord 中删除该网络钩子，创建新的，并更新 TrucklineMP 上的配置。

**根据职责分配权限。** 并非每位官员都需要 `announcements.manage` 权限。对于许多角色而言，仅具备查看和测试权限就足够了。

**部署后检查投递日志。** 如果 Discord 返回 404 错误，说明网络钩子已在 Discord 端被删除。请创建新的网络钩子并粘贴新 URL。

## 故障排除

### Discord 中未出现任何消息

- 确认网络钩子已 **启用**，且相应 **事件也已启用**。
- 检查 **投递日志** 中的失败记录。
- 确认 Discord 服务器设置中的网络钩子仍然存在。
- 确认您的 VTC 已启用 VTC 公告模块。

### 消息之前能正常发送，现在却停止了

- 网络钩子可能在多次失败后被 **自动禁用**。修复 URL 后重新启用即可。
- Discord 可能已删除该网络钩子。请创建新的网络钩子。

### 测试消息正常，但真实事件未触发

- 该事件可能已被禁用，或受某项 **条件**（静默时段、招募开放状态、所需角色）限制。
- 每日摘要模式会将消息排队，直到摘要发布时才统一发送。

### 消息中的名称错误或信息缺失

- 检查您的模板变量。拼写错误（如 `{member.name}` 与 `{target.name}`）会导致显示错误的人员。
- 即使自定义模板中省略了变量，消息仍会正常发送，但不会包含动态数据。
