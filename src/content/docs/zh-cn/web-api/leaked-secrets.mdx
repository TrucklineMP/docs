如果 TrucklineMP 的敏感信息——包括公共 API 密钥（`tlmp_api_...` 或旧版 `tl_...` 密钥）、OAuth 客户端敏感信息（`tlmp_secret_...`）、OAuth 令牌（`tlmp_oat_...` / `tlmp_ort_...`）或 webhook 签名敏感信息——被提交到公共代码库、粘贴到公共频道或以其他方式暴露，请立即将其视为已泄露，并按照以下步骤操作。

TrucklineMP 已接入 [GitHub 敏感信息扫描](https://docs.github.com/en/code-security/secret-scanning/about-secret-scanning)。如果 GitHub 在公共代码库中检测到 TrucklineMP 敏感信息模式，本页面即为该警报中提供的修复指南。

## 1. 立即轮换敏感信息

已暴露的敏感信息应被视为已泄露，而不仅仅是“有风险”。轮换操作会将泄露的值从服务中移除，无论其是否已被滥用。

### API 密钥（`tlmp_api_...` 或旧版 `tl_...` 密钥）

1. 登录并打开 [开发者控制台](https://trucklinemp.com/developer)。
2. 选择该密钥所属的项目。
3. 删除已暴露的密钥并生成新密钥。
4. 更新所有使用该密钥的地方（服务器、CI 敏感信息、机器人等）。旧密钥在删除的瞬间即失效。

### OAuth 客户端敏感信息

1. 打开 [开发者控制台](https://trucklinemp.com/developer) → **OAuth 应用** → 您的应用。
2. 从应用设置中重新生成客户端敏感信息。
3. 更新应用服务器端配置中的敏感信息。现有用户会话不受影响，但任何仍使用旧敏感信息的代码在获取新令牌时将失败。

### webhook 签名敏感信息

1. 打开 [开发者控制台](https://trucklinemp.com/developer) → **webhook** → 受影响的订阅。
2. 重新生成签名敏感信息。
3. 更新您的 webhook 接收端，以使用新敏感信息验证签名。

## 2. 从源代码历史中删除敏感信息

仅删除文件或在新提交中移除相关行是**不够的**——敏感信息仍会保留在 git 历史中。您需要重写历史以彻底清除：

- [GitHub：从代码库中删除敏感数据](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)
- 工具：[git filter-repo](https://github.com/newren/git-filter-repo) 或 [BFG Repo-Cleaner](https://rtyley.github.io/bfg-repo-cleaner/)

如果代码库是公开的且已被克隆或分叉，即使重写了历史，也应认为旧值已永久暴露——真正保护您账户的是步骤 1 的轮换操作，而非历史清理。

## 3. 检查是否已被滥用

- API 密钥：在开发者控制台的分析/审计日志中，检查项目相关的请求量和来源。
- OAuth 应用：检查近期授权中是否有您不认识的用户。
- webhook：检查近期交付中，目标端点是否有异常活动。

如果您发现任何非您发起的活动，请联系支持团队（见下文），以便团队进一步调查。

## 4. 防止未来泄露

- 切勿将敏感信息提交到源代码控制中。请使用环境变量或敏感信息管理工具。
- 添加提交前钩子或 CI 检查（例如 [gitleaks](https://github.com/gitleaks/gitleaks)、[trufflehog](https://github.com/trufflesecurity/trufflehog)），在敏感信息被推送前将其拦截。
- 为 OAuth 应用和 API 密钥分配仅满足集成所需的最小权限。

## 报告泄露或可疑活动

如果您认为 TrucklineMP 敏感信息已泄露或被滥用，且需要超出自行轮换范围的支持，请联系：

- **Discord：** [https://discord.gg/trucklinemp](https://discord.gg/trucklinemp)
- **电子邮件：** support@trucklinemp.com
